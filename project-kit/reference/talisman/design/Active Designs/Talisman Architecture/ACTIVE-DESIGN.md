   Owners, tasks, branches and worktrees do not automatically require folders or prove activity.
2. Every front door identifies status, owner/authority, objective, implemented baseline with evidence,
   remaining work, dependencies/gates and acceptance. Multiple concurrent designs need distinct names.
3. Keep supporting TEST-PLAN, HANDOFF, decisions, evidence and references only while needed by that
   living design. A historical receipt is not an active design merely because a current page cites it.
4. Classify every existing document, including mixed folders, by evidence: current design; enduring
   current contract/reference; completed; inactive/paused; superseded/history; unresolved status.
   A paused but still actively maintained design must state its exact gate; dormancy alone is not proof.
5. Preserve completed designs in `design/Completed Designs/`; preserve inactive/history material in a
   clearly labelled archive there, without calling it completed. Enduring current contracts retain their
   proper architecture/reference home. Do not archive implemented contracts as obsolete plans.
6. Record each old path, classification evidence, destination, retained dependencies and inbound readers
   in a migration manifest. Preserve bytes for moves except separately identified link/status updates.
   Update local Markdown, indexes and other readers in the same coherent patch. Never delete evidence.
7. Unknown status stays explicitly unresolved in the inventory, not silently active or completed. Finish
   every evidence-supported classification; name the exact owner decision needed for the remainder.
8. Reactivation restores a maintained front door with new authority and retained provenance. Completion
   moves the body out of Active Designs and removes its current index entry in the same patch.
