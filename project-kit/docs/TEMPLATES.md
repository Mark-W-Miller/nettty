# Using document examples

Place and Character JSON files and schemas illustrate component shapes/defaults; they are not executable
materialization code or validated live records. Stable identity, hierarchy, coordinates/units, revisions,
provenance and unresolved references must be made explicit in each project's contracts. Character sheets,
Morph/appearance/motion, inventory, relationships and ownership remain project-owned. Reject unsafe guesses
in implementation; document which defaults and extension points your project actually supports.
