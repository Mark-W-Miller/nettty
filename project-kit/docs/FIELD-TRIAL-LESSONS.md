# Reusable field-trial lessons

Curated from Insect Wars DATABASE-ADOPTION, SCENE-AND-DATABASE-SEAMS and NEXT-PASS supplements.
Riverwild feature assignments, numeric field size and game-specific return formats remain local.

- Preserve the accepted current project baseline and identify exact source/content/build bytes. A
  preview and a returned source package must derive from the same source; user-reported differences
  are feedback until diagnosed, not established technical causes.
- Use complete native reusable object definitions and explicit instances. Procedural meshes are
  projections. Missing terrain adapters remain named dependencies, not invented database bindings.
- Design physical extent, elevation sampling and texture scale together. More pixels alone do not
  enlarge a Place. Deliberately flat numeric height is allowed by the shared Place contract.
- Distinguish local staging checks from actual owning-validator acceptance. The first ten Morph
  candidates passed staging checks but failed static comparison on stances/keyframes/interpolation.
- Continue independent authorized work when a capability is missing; return exact missing operations,
  responsible owners and affected acceptance gates. Record local decisions and friction for Atlas.
- Separate hosting from database binding. Standalone bundled content can be labelled honestly while
  native admission remains pending. Confirm actual host route/security/asset support rather than
  borrowing another registered component's upload command or assuming an extra server is necessary.
- For hosted delivery, record selected component identity and matching served bytes, then browser
  acceptance. A package, screenshot, catalog probe or planned test cannot stand in for those outcomes.

These are reusable documentation lessons, not instructions to implement Riverwild features elsewhere.
No hosting, native validation or database mutation was performed during Kit assembly.
